# Bug Reproduction Adapter

Use when a defect needs reproducible evidence, especially incomplete,
intermittent or environment-specific reports. Reuse a sufficient existing
reproduction; do not rerun expensive or consequential operations just to fill a
template.

Select `bug-reproduction` with `accord-route.mjs`, then load its returned method
IDs and resolve their use/preflight conditions. The default is
`--method bug-reproduction-brief`, not an override of a reviewed project binding.
Read the packet completely. The default Accord adapter turns the MIT method's
stop-before-repair rule to a phase boundary within the user's actual task.

## Establish and preserve evidence

Record observable expected and actual behavior separately from suspected
causes. Use current user intent and approved inputs to establish the expected
result; an old test is not a veto on an authorized behavior change. Inspect
the relevant revision/worktree, runtime, lockfile and environment facts without
guessing configuration or exposing secrets.

Reduce the failure to the smallest safe input, steps and fixture. Check
repeatability when safe; distinguish deterministic, intermittent and not
reproduced outcomes. Keep evidence before changing the failing implementation.
Reference existing tests and logs; place authorized new regression fixtures in
the project's existing test locations. Do not create a mandatory brief file.

## Continue according to task scope

| User task | After the reproduction phase |
| --- | --- |
| Reproduce only | Report evidence, repeatability and unknowns, then stop. |
| Diagnose without repair | Continue causal investigation and report its evidence; do not repair. |
| Fix the defect | Continue diagnosis, authorized implementation and regression checks under the existing Accord gates. Do not request settled repair authority again. |

An unconfirmed reproduction is not a root cause or a reason to loop indefinitely.
Bound attempts, inspect other relevant evidence, and report the remaining
uncertainty. If that uncertainty prevents a justified repair, explain the
specific missing evidence; do not claim success. A new material design choice
still follows the normal Decision Frontier.

Use the response for read-only work and the existing Change for material work.
Record applied method/revision, commands, results and limitations; link evidence
instead of duplicating it in project knowledge. After repair, check the original
failure and affected behavior against the approved inputs and intended use.

An absent legacy route requires a reviewed upgrade before integrated method
use. An unavailable verified method is reported explicitly; continue ordinary
diagnosis or repair where possible using this procedure without claiming that
the upstream method ran. Neither fallback authorizes new dependencies or scope.
