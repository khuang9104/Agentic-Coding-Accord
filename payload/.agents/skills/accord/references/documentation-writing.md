# Documentation Writing Adapter

Use for a substantive documentation-writing or readability request, including
READMEs, how-to guides, reference and explanations. A typo or formatting-only
edit needs no method. Initial project discovery and factual refresh remain in
`knowledge-acquisition.md`; this adapter improves the requested document.

Select `documentation-writing` with `accord-route.mjs`, then load its returned
method IDs. The default is `--method documentation-writer`; a reviewed project
replacement takes precedence over that example. Read its execution packet and
resolve its use/preflight conditions. The default reviewed excerpts supply writing
methods; the Accord contract owns scope and workflow. Full upstream text is
available only when auditing with `--view audit`, not needed for ordinary writing.

## Apply to the requested document

- Infer audience, reader goal, scope and document type from the request and
  existing material. Ask only when a missing choice would materially change
  the result. Reuse a suitable outline; the upstream mandatory outline approval
  does not add a pause to already authorized writing.
- Distinguish learning steps, problem-solving instructions, exact reference and
  explanation where useful. These are writing choices, not four required
  directories or four documents. Preserve the requested language and style.
- Begin with current project documents. Check targeted code, configuration,
  schemas or tests for missing, stale or conflicting facts. Route to knowledge
  acquisition only when evidence is actually insufficient; do not rescan the
  project merely to improve wording.
- Write only the requested file or agreed sections, preserving existing
  authorship and canonical owners. Do not create a second project summary or
  duplicate requirements, Design Inputs or V&V records. For managed knowledge,
  retain its structure, provenance and freshness rules and refresh the compact
  context only if the summarized facts change.
- Verify technical names, links and instructions against evidence. Report
  unexecuted examples honestly; a copyedit need not run every documented
  command or modify project behavior.

Report the applied method, revision, target documents and relevant checks.
Material work uses existing Capability Use/Record fields; a small edit does
not require a new Change solely because this method was used.

If the route is absent in a legacy configuration, report that a reviewed route
upgrade is needed; continue authorized writing with ordinary tools. If the
verified method is unavailable, report that limitation and use this local
procedure without claiming upstream method use. Do not install or download a
replacement silently.
